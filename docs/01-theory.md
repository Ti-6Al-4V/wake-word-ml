# Теория

Как нейросеть распознаёт слово на микроконтроллере. От звука до inference.

---

## 1. Звук → PCM

Звук — волна давления воздуха. Микрофон (INMP441) преобразует её в электрический сигнал, АЦП оцифровывает.

**PCM (Pulse Code Modulation):**
- Частота дискретизации: 16 kHz (16000 сэмплов в секунду)
- Разрешение: 16-bit (значения от -32768 до 32767)
- Канал: 1 (моно)

```
Воздушная волна → мембрана → АЦП → PCM сэмплы
                                    [-120, -85, -30, 10, 55, 98, ...]
```

1 секунда аудио = 16000 чисел int16. В RAM = 32 KB.

---

## 2. PCM → Спектрограмма

Нейросети не работают с сырым PCM. Звук преобразуют в **спектрограмму** — визуальное представление частот во времени.

### FFT (Быстрое преобразование Фурье)

Разбивает сигнал на частотные составляющие. Из "волны" получает "какие частоты присутствуют и с какой амплитудой".

```
PCM (время) → FFT → частотный спектр
                     [50Hz: 0.3, 100Hz: 0.8, 200Hz: 0.5, ...]
```

### Окна (frames)

Аудио разбивается на короткие окна (~30мс), для каждого окна — свой FFT. Это даёт изменение частот во времени.

```
Аудио 1 сек → 30 окон по 30мс → для каждого FFT → матрица [частоты × время]
```

### Mel-шкала

Человеческий слух нелинеен: мы лучше различаем низкие частоты чем высокие. **Mel-шкала** — логарифмическая шкала частот, имитирующая слух.

```
Hz: 0 ... 1000 ... 2000 ... 4000 ... 8000
Mel: 0 ... 1000 ... 1543 ... 2146 ... 2840
```

Частоты сжимаются: больше деталей на низких, меньше на высоких.

---

## 3. MFCC (Mel-Frequency Cepstral Coefficients)

**MFCC** — стандартный способ извлечения признаков из речи для ML. Компактен, содержит информацию о форме речевого тракта.

### Как получается:

```
PCM окно (30мс, 480 сэмплов)
    │
    ▼ 1. Pre-emphasis (фильтр верхних частот)
    │
    ▼ 2. Hamming window (сглаживание краёв)
    │
    ▼ 3. FFT → спектр мощности
    │
    ▼ 4. Mel filterbank (20 треугольных фильтров)
    │    → 20 mel-частотных полос
    │
    ▼ 5. Log (логарифм амплитуды)
    │
    ▼ 6. DCT (дискретное косинусное преобразование)
    │    → 20 коэффициентов MFCC
    │
    ▼
MFCC: [c1, c2, c3, ..., c20] — 20 чисел на окно
```

### Почему MFCC а не сырая спектрограмма:

- MFCC: 20 чисел на окно (компактно)
- Спектрограмма: 256 чисел на окно (избыточно)
- MFCC учитывает слуховую систему (mel + log)
- DCT убирает корреляцию между частотами

### Размер входа для нейросети

```
1 сек аудио = ~33 окна × 30мс
Каждое окно = 20 MFCC коэффициентов
Вход нейросети: матрица [33 × 20] = 660 чисел
```

## 4. Нейросеть (CNN)

**CNN (Convolutional Neural Network)** — тип нейросети, который ищет паттерны в данных. Для изображения — паттерны в пикселях. Для речи — паттерны в MFCC.

### Архитектура для wake word:

```
Вход: [33 × 20] MFCC матрица
    │
    ▼
Conv2D (16 фильтров, 3×3) → ReLU
    │
    ▼
MaxPool (2×2)
    │
    ▼
Conv2D (8 фильтров, 3×3) → ReLU
    │
    ▼
MaxPool (2×2)
    │
    ▼
Flatten
    │
    ▼
Dense (16) → ReLU
    │
    ▼
Dense (1) → Sigmoid → [0.0 ... 1.0]
    │
    ▼
score > 0.5 → wake word detected
```

### Слои:

**Conv2D** — свёрточный слой. "Скользит" фильтром по матрице, ищет локальные паттерны. Например, паттерн "резкий переход частоты" = согласный звук.

**ReLU** (Rectified Linear Unit) — функция активации. `f(x) = max(0, x)`. Убирает отрицательные значения, добавляет нелинейность.

**MaxPool** — уменьшает размер. Берёт максимум из окна 2×2. Снижает вычисления, делает модель устойчивой к сдвигам.

**Flatten** — превращает матрицу в вектор (для полносвязного слоя).

**Dense** — полносвязный слой. Каждый нейрон связан со всеми входами. Финальная классификация.

**Sigmoid** — сжимает выход в [0, 1]. 1 = wake word, 0 = не wake word.

### Размер модели:

```
Conv2D 16: 16 × (3×3×1) + 16 = 160 параметров
Conv2D 8:  8 × (3×3×16) + 8  = 1160 параметров
Dense 16:  16 × вход + 16
Dense 1:   1 × 16 + 1
```

~2000-5000 параметров. В .tflite — ~20-100 KB. Помещается в PSRAM ESP32-S3 (8MB).

## 5. Обучение

### Датасет

Нейросеть учится на примерах. Нужны:

**Позитивные (wake word):**
- ~500-2000 записей слова "гермес"
- Разные голоса, громкости, темпы
- Разные расстояния до микрофона
- Разный шум фона

**Негативные (не wake word):**
- ~2000-5000 записей других слов, фраз, шумов
- Тишина, музыка, разговоры, уличный шум
- Похожие слова ("гермес" vs "германий", "серьёзно")

### Процесс:

```
Датасет (MFCC)
    │
    ▼
Модель (CNN, случайные веса)
    │
    ▼
Forward pass: MFCC → prediction
    │
    ▼
Loss: prediction vs label (binary crossentropy)
    │
    ▼
Backprop: градиенты по весам
    │
    ▼
Optimizer (Adam): обновляем веса
    │
    ▼
Повторяем N эпох
    │
    ▼
Обученная модель
```

**Binary crossentropy:**
```
loss = -[y·log(p) + (1-y)·log(1-p)]
```
где y = правильный ответ (0 или 1), p = предсказание модели.

**Adam optimizer** — адаптивный градиентный спуск. Автоматически подбирает learning rate для каждого параметра.

### Overfitting

Если модель слишком умная или датасет маленький — модель "запоминает" примеры вместо обобщения. На новых данных работает плохо.

**Mitigation:**
- Dropout (выключаем случайные нейроны при обучении)
- Data augmentation (добавляем шум, меняем pitch, скорость)
- Валидационный датасет (отдельная часть для проверки)

## 6. Inference на ESP32-S3

### TensorFlow Lite Micro

TFLite Micro — версия TensorFlow для микроконтроллеров. Работает с .tflite моделями, не требует ОС, ~300 KB кода.

### Пайплайн на ESP32:

```
I2S → PCM буфер (1 сек, 16000 сэмплов)
    │
    ▼
MFCC извлечение (на ESP32, библиотека or своя)
    │ → матрица [33 × 20]
    ▼
TFLite Micro: model->invoke()
    │ → score [0.0 ... 1.0]
    ▼
score > THRESHOLD → wake!
```

### Память:

- Модель: ~20-100 KB (в Flash через PROGMEM или SPIFFS)
- MFCC буфер: ~2 KB (на окно)
- TFLite tensors: ~10-50 KB (в PSRAM)
- Итого: <200 KB из 8MB PSRAM

### Скорость:

- MFCC извлечение: ~5мс на окно
- CNN inference: ~10-30мс
- Полный цикл: ~35-40мс
- Частота проверки: каждые 30мс (real-time)

### Потребление:

- CPU active: ~80 mA
- Без WiFi: ~50 mA
- Light sleep между окнами: ~30-40 mA

## 7. Почему это работает

**Слово "гермес" = уникальный паттерн MFCC:**

```
"г" — взрывной согласный, резкий низкочастотный всплеск
"е" — гласный, ровный спектр с формантами
"р" — дрожащий согласный, периодические всплески
"м" — носовой согласный, низкочастотный гул
"е" — гласный
"с" — шипящий, высокочастотный шум
```

Каждый звук = уникальный набор MFCC. Последовательность = уникальный паттерн. CNN учится находить этот паттерн.
