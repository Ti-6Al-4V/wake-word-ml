# Теория: сигнал, признаки, градиенты и вычисления

Практика и порядок изучения — [00-learning-path](00-learning-path.md),
проверочные задачи — [10-labs](10-labs.md). Ниже формулы для текущего
пайплайна, а не утверждение, что эта конфигурация оптимальна.

## 1. PCM и дискретизация

Для sample rate fs момент отсчёта n равен `t=n/fs`. PCM16 хранит целые
числа −32768..32767; чтение делит их на 32768. Моно — один канал.
WAV является контейнером и может содержать разные форматы; наши утилиты
ожидают несжатый PCM16. FLAC тоже сохраняет данные без потерь.

16 kHz — практичный выбор для маленькой речевой модели. Частоты выше
8 kHz не представимы без aliasing. Перед понижением частоты их нужно
подавить фильтром; простое прореживание этого не делает. Речь не строго
ограничена 8 kHz, поэтому «48 kHz не содержит полезной информации» неверно.

```
RMS(x) = sqrt(mean(x²))
dBFS_RMS = 20*log10(RMS(x)/1.0)
SNR_dB = 10*log10(P_signal/P_noise)
```

Смешивая независимый шум с сигналом, его масштаб выбирают по RMS.
SNR 5 dB означает отношение мощностей около 3.16; восприятие зависит
от спектра и характера шума. Белый шум не имитирует разговоры или улицу.

Пиковая нормализация `0.9*x/max(abs(x))` меняет масштаб, но не улучшает
SNR и может сильно усилить фон. Клиппинг теряет информацию и нелинеен.

## 2. Спектр и окна

```
X[k] = Σ(n=0..N−1) x[n] * exp(−i*2π*k*n/N)
power[k] = |X[k]|²
frequency[k] = k*fs/N
```

FFT — эффективный алгоритм DFT. Для вещественного входа достаточно
N/2+1 бинов. При FFT 512 и fs=16000 это **257 бинов**, не mel-полос.
В нашем коде FFT не нормируется, поэтому абсолютная энергия зависит
от N, окна и масштаба входа.

Кадр 480 отсчётов (30 мс), шаг 480. Кадры не перекрываются. Окно
Хэмминга `0.54−0.46*cos(2πn/(479))` ослабляет края и боковые лепестки
спектра, расширяя основной лепесток. Шаг 10 мс с перекрытием — разумный
кандидат для отдельного эксперимента; он меняет размер входа и стоимость.
Дополнение кадра до FFT 512 уплотняет спектральную сетку, не добавляя
информации. Оконная функция — не то же самое, что окно классификатора 1.2с.

## 3. Log-mel и MFCC

Нейросети могут работать с PCM, спектрами, log-mel или MFCC. Здесь
выбраны ручные признаки для компактного и понятного первого варианта.

1. Pre-emphasis: `y[n]=x[n]−0.97*x[n−1]`; поднимает высокие частоты
   относительно низких. Это настройка frontend, а не обязательный закон.
2. Кадр, Хэмминг, FFT, power.
3. 20 треугольных фильтров: `E[m]=Σ bank[m,k]*power[k]`.
   Границы равномерны в шкале `mel(f)=2595*log10(1+f/700)`.
4. `u[m]=ln(max(E[m],1e−5))`.
5. `c[q]=Σ u[m]*cos(π*q*(m+0.5)/20)` — DCT-II без нормирующего множителя.
6. По каждому q: `(c[t,q]−mean_t(c[:,q]))/(std_t(c[:,q])+1e−5)`.

20 log-mel полос превращаются в 20 MFCC: DCT здесь обратима до последующей
нормализации, число значений не сокращается. Низкие номера коэффициентов
описывают плавные изменения формы log-спектра, высокие — более быстрые.
DCT часто уменьшает корреляции, но не гарантирует независимости признаков.
Ось q — **номер коэффициента**, не частота и не номер фонемы.

CMVN удаляет временное среднее каждого коэффициента и меняет масштаб.
Для постоянного коэффициента дисперсия остаётся нулевой, а не единичной.
Среднее и дисперсия накапливаются в f64 из f32-признаков; нормализованный
результат возвращается в f32. Это предотвращает усиление ошибки округления
среднего на почти постоянном сигнале.
Норма MFCC после CMVN не равна физической энергии кадра; используй RMS PCM.

В идеализированном случае масштаб амплитуды становится постоянной добавкой
после log и удаляется CMVN. При log-floor, шуме, квантовании и клиппинге
совпадение не гарантировано. Для потока и train нужен одинаковый frontend.
`1e−5` в ненормированной mel-энергии нельзя прямо объявить «−60 dBFS».

Дополнение коротких файлов синтетическим шумом уменьшает один возможный
артефакт длины, но само может стать признаком источника. Текущий равномерный
шум имеет peak 0.001 (−60 dBFS), RMS примерно 0.000577 (−64.8 dBFS).
Это не измеренный шумовой профиль микрофона и не универсальная защита от утечек.

## 4. Нейрон, loss и backprop

```
z = Σ w_i*x_i + b
p = 1/(1+exp(−z))
L = −y*ln(p) − (1−y)*ln(1−p)
  = max(z,0) − y*z + ln(1+exp(−abs(z)))
```

Последняя форма устойчива для больших конечных логитов. При y=0,z=100
штраф около 100. Ограничение p через clamp искусственно обрезает штраф.
При p=0.5 BCE=ln(2); для константного оптимального предсказания p=доля
позитивов loss равен энтропии этой доли, не обязательно 0.69.

Цепное правило:

```
dL/dp = −y/p + (1−y)/(1−p)
dp/dz = p*(1−p)
dL/dz = p−y
dL/dw_i = (p−y)*x_i
dL/db = p−y
```

Для батча усредняем производные; SGD: `θ ← θ−lr*gradient`.
Для Dense `Z=XW+b`: `dW=Xᵀ*dZ`, `dX=dZ*Wᵀ`, `db=sum_batch(dZ)`
(учти усреднение loss ровно один раз). ReLU пропускает производную при
положительном входе, tanh имеет производную `1−tanh²(x)`.

Backprop вычисляет эти производные от конца графа к началу; autodiff
автоматизирует тот же алгоритм. Это не поиск по всем наборам весов.
Adam ведёт моменты градиента, корректирует их начальное смещение и
масштабирует шаг; базовый lr остаётся гиперпараметром.

Dropout случайно обнуляет часть активаций в train; в inference выключен.
Weight decay ограничивает рост весов. L2 с Adam и decoupled AdamW —
разные алгоритмы; в проекте используется `AdamConfig` с `WeightDecayConfig`.
Регуляризация может помочь, но улучшение нужно измерять.

Sigmoid-score не гарантирует калиброванную вероятность в эксплуатации.
Порог выбирается по цене и частоте ошибок на development-данных.

## 5. Архитектура и стоимость

| Слой | Выход без batch | Параметры | MAC (без bias/активации) |
|---|---|---:|---:|
| Вход | 1×40×20 | 0 | 0 |
| Conv1 3×3, valid | 16×38×18 | 160 | 98 496 |
| Pool 2×2 | 16×19×9 | 0 | сравнения |
| Conv2 3×3, valid | 8×17×7 | 1160 | 137 088 |
| Pool 2×2 | 8×8×3 | 0 | сравнения |
| Flatten, Dropout | 192 | 0 | — |
| Dense + ReLU | 16 | 3088 | 3072 |
| Dense | 1 | 17 | 16 |
| Итого | logit | **4425** | **238 672** |

Для valid-свёртки stride=1 выход `H−K+1`; параметры
`C_out*(C_in*K_h*K_w+1)`, MAC без bias —
`H_out*W_out*C_out*C_in*K_h*K_w`. MAC не равен числу параметров.
Один MAC — умножение с накоплением; перевод в FLOP зависит от соглашения.

Одинаковый фильтр применяется во всех позициях. Это полезное ограничение
модели, но не гарантия инвариантности всей сети. Края, stride, pooling и
Flatten→Dense влияют на ответ при сдвиге. Для MFCC соседство коэффициентов
не эквивалентно соседству частот; сравнение с log-mel — обязательная гипотеза.

## 6. Проверка и перенос

Train меняет веса; val выбирает модель и параметры; final test измеряет
результат после выбора. Подглядывание в test при каждой итерации делает
его development-набором, даже без backward на нём.

Риск переобучения нельзя вычислить делением числа весов на число записей.
Проверяй learning curves, зависимость от условий и результаты на новых
сессиях. Аугментации зависимы от оригиналов и друг от друга.

Окно-классификатор и потоковый детектор имеют разные метрики:
[07-quality](07-quality.md). RAM включает промежуточные активации,
аудиобуфер, FFT scratch, стек и рантайм. Float-веса занимают 17.7 kB,
описанные буферы — около 100.9 kB RAM до дополнительного overhead.
Время и ток нужно измерять на конкретной сборке: [04-deploy](04-deploy.md).
