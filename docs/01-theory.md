# Теория

Как нейросеть распознаёт слово на микроконтроллере. От звука до inference.

---

## 1. Звук → PCM

Звук — волна давления воздуха. Микрофон (INMP441) преобразует её в электрический сигнал, АЦП оцифровывает.

**PCM (Pulse Code Modulation):**
- Частота дискретизации: 16 kHz (16000 сэмплов в секунду)
- Разрешение: 16-bit (значения от -32768 до 32767)
- Канал: 1 (моно)

```
Воздушная волна → мембрана → АЦП → PCM сэмплы
                                    [-120, -85, -30, 10, 55, 98, ...]
```

1 секунда аудио = 16000 чисел i16. В RAM = 32 KB.

---

## 2. PCM → Спектрограмма

Нейросети не работают с сырым PCM. Звук преобразуют в **спектрограмму** — частотное представление во времени.

### FFT (Быстрое преобразование Фурье)

Разбивает сигнал на частотные составляющие. Из "волны" получает "какие частоты присутствуют и с какой амплитудой".

```
PCM (время) → FFT → частотный спектр
                     [50Hz: 0.3, 100Hz: 0.8, 200Hz: 0.5, ...]
```

### Окна (frames)

Аудио разбивается на короткие окна (~30мс), для каждого — свой FFT. Это даёт изменение частот во времени.

```
Аудио 1 сек → 33 окна по 30мс → для каждого FFT → матрица [частоты × время]
```

### Mel-шкала

Человеческий слух нелинеен: мы лучше различаем низкие частоты. **Mel-шкала** — логарифмическая шкала, имитирующая слух.

```
Hz: 0 ... 1000 ... 2000 ... 4000 ... 8000
Mel: 0 ... 1000 ... 1543 ... 2146 ... 2840
```

---

## 3. MFCC (Mel-Frequency Cepstral Coefficients)

**MFCC** — стандарт извлечения признаков из речи для ML. Компактен, содержит информацию о форме речевого тракта.

### Цепочка преобразований:

```
PCM окно (30мс, 480 сэмплов)
    │
    ▼ 1. Pre-emphasis (фильтр верхних частот)
    │
    ▼ 2. Hamming window (сглаживание краёв)
    │
    ▼ 3. FFT → спектр мощности
    │
    ▼ 4. Mel filterbank (20 треугольных фильтров)
    │    → 20 mel-частотных полос
    │
    ▼ 5. Log (логарифм амплитуды)
    │
    ▼ 6. DCT (дискретное косинусное преобразование)
    │    → 20 коэффициентов MFCC
    │
    ▼
MFCC: [c1, c2, c3, ..., c20] — 20 чисел на окно
```

### Размер входа для нейросети

```
1 сек аудио = ~33 окна × 30мс
Каждое окно = 20 MFCC коэффициентов
Вход нейросети: матрица [33 × 20] = 660 чисел
```

---

## 4. Нейросеть (CNN)

**CNN (Convolutional Neural Network)** — ищет паттерны в данных. Для речи — паттерны в MFCC матрице.

### Архитектура:

```
Вход: [1, 33, 20] (1 канал, MFCC матрица)
    │
    ▼
Conv2D (16 фильтров, 3×3) → ReLU
    │
    ▼
MaxPool (2×2)
    │
    ▼
Conv2D (8 фильтров, 3×3) → ReLU
    │
    ▼
MaxPool (2×2)
    │
    ▼
Flatten
    │
    ▼
Dense (16) → ReLU
    │
    ▼
Dense (1) → Sigmoid → [0.0 ... 1.0]
    │
    ▼
score > 0.5 → wake word detected
```

### Слои:

**Conv2D** — свёрточный слой. Фильтр "скользит" по матрице, ищет локальные паттерны. Например, паттерн "резкий переход частоты" = согласный звук.

**ReLU** (Rectified Linear Unit) — `f(x) = max(0, x)`. Убирает отрицательные значения, добавляет нелинейность.

**MaxPool** — уменьшает размер. Берёт максимум из окна 2×2. Меньше вычислений, устойчивость к сдвигам.

**Flatten** — матрица → вектор (для полносвязного слоя).

**Dense** — полносвязный слой. Каждый нейрон связан со всеми входами.

**Sigmoid** — сжимает выход в [0, 1]. 1 = wake word, 0 = не wake word.

### Размер модели:

~5000 параметров. Бинарные веса = ~5 KB. Float32 = ~20 KB.

## 5. Обучение на burn

### Датасет

| Категория | Что | Кол-во |
|-----------|-----|--------|
| Позитивные | слово "гермес" | 500-2000 |
| Негативные | другие слова, фразы, шум | 2000-5000 |
| Фон | тишина, музыка, улица | 500 |

### Процесс:

```
Датасет (MFCC матрицы)
    │
    ▼
Модель (CNN, случайные веса)
    │
    ▼
Forward pass: MFCC → prediction
    │
    ▼
Loss: prediction vs label (binary crossentropy)
    │
    ▼
Backprop: градиенты по весам
    │
    ▼
Optimizer (Adam): обновляем веса
    │
    ▼
Повторяем N эпох → обученная модель
```

**Binary crossentropy:**
```
loss = -[y·log(p) + (1-y)·log(1-p)]
```
где y = правильный ответ (0 или 1), p = предсказание модели.

**Adam optimizer** — адаптивный градиентный спуск. Автоматически подбирает learning rate.

### Overfitting

Модель "запоминает" примеры вместо обобщения. Mitigation:
- Dropout (выключаем случайные нейроны при обучении)
- Data augmentation (добавляем шум, меняем pitch, скорость)
- Валидационный датасет (отдельная часть для проверки)

## 6. Inference на ESP32-S3

### Почему ручной C++ а не TFLite

Модель: 2 Conv2D + 2 Dense = ~5000 параметров. Ручной forward pass — ~200 строк C++. Никаких рантаймов, никаких зависимостей.

### Пайплайн:

```
I2S → PCM буфер (1 сек, 16000 сэмплов)
    │
    ▼
MFCC извлечение (FFT + mel + DCT, на C)
    │ → матрица [33 × 20]
    ▼
CNN forward pass (Conv2D → ReLU → MaxPool → Dense → Sigmoid)
    │ → score [0.0 ... 1.0]
    ▼
score > THRESHOLD → wake!
```

### Память:

| Компонент | Размер |
|-----------|--------|
| Веса модели (f32) | ~20 KB |
| Веса модели (q8) | ~5 KB |
| MFCC буфер | 2.6 KB |
| Conv промежуточные | ~10 KB |
| **Итого** | **<40 KB** |

### Скорость:

| Операция | Время |
|----------|-------|
| MFCC (FFT + mel + DCT) | ~5мс |
| CNN forward pass | ~5-10мс (без TFLite, просто матрица) |
| Полный цикл | ~15мс |
| Проверка | каждые 300мс |

## 7. Почему это работает

Слово "гермес" = уникальная последовательность звуков:

```
"г" — взрывной согласный, резкий низкочастотный всплеск
"е" — гласный, ровный спектр с формантами
"р" — дрожащий согласный, периодические всплески
"м" — носовой согласный, низкочастотный гул
"е" — гласный
"с" — шипящий, высокочастотный шум
```

Каждый звук = уникальный набор MFCC. Последовательность = уникальный паттерн. CNN учится находить этот паттерн.
