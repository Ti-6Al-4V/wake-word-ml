# 09 — Как выбирать размеры датасета

Зачем этот файл: числа вроде «300 дублей», «6000 негативов» — не вывод
из формулы, а обоснованные эвристики. Здесь — аргументация, на которой
они стоят, чтобы перед каждым «доgather ещё?» можно было освежить голову
за две минуты.

## TL;DR

Точной формулы размера датасета нет. Есть три якоря:

1. **статистика оценки** — сколько данных нужно, чтобы *измерить* качество
2. **покрытие вариативности** — сколько нужно модели, чтобы обобщать
3. **требования главной метрики** — сколько негативов требует FA ≤1/10ч

А окончательный арбитр — **кривая обучения** на подмножествах. Данные
добавляем, пока она растёт.

---

## Якорь 1 — статистика оценки (главный аргумент для 300)

Неочевидный факт: **данные нужны в первую очередь оценке, а не модели.**

TPR ≥95% надо *измерить*, и измерение доли подчиняется биномиальной
статистике. Погрешность ±E при доверии 95%:

```
n = 1.96² · p(1−p) / E²
```

| Погрешность | Нужен тест из |
|-------------|---------------|
| ±5%         | ~73 записей   |
| ±3%         | ~203          |
| ±2%         | ~456          |

Тест обязан быть **живыми независимыми записями**: аугментированные
копии дублей из train — это утечка (модель их уже видела), на них
оценка врёт. Значит: тест ~150 живых дублей + train ~200 других живых
дублей + запас на брак = **300–500**. Отсюда и число.

## Якорь 2 — покрытие вариативности (почему не 5000)

Слово в жизни варьируется по осям:

```
громкость/расстояние · темп · высота голоса · шум вокруг
артикуляция (чётко/бормотание) · состояние (сонный, простуженный)
микрофон · комната
```

Модель обобщает, когда видела представителей **каждой оси**. Сырые
повторы в одних и тех же условиях почти ничего не добавляют — поэтому:

- **живые дубли = скелет вариативности** (их ничем не заменить)
- **аугментация = мясо на скелете**: множит оси механически (шум, темп,
  громкость, сдвиг), ×9 на исходник

После пары сотен дублей одного диктора в одной комнате наступает
**убывающая отдача**: ценнее становится не «больше», а «другое» — другой
микрофон (INMP441 из кепки), улица, другое состояние голоса. Это смысл
фазы 2 из [07-quality](07-quality.md): не добирать дубли на диване,
а менять условия.

## Якорь 3 — негативы и главная метрика

Главная метрика — false accepts ≤1 в 10 часов. 10 часов аудио окнами
по 1.2с = **~30 000 окон**. Чтобы ошибаться ≤1 раза на 30 000, область
«нет» должна быть густо покрыта негативами. Формулы тут нет, но есть
два правила:

- **Баланс классов.** Негативов должно быть не меньше позитивов;
  нормальная вилка для wake word — от 1:1 до 10:1 в пользу негативов.
  У нас после аугментации ~3000 позитивов и 6000 негативов → 1:2.
- **Трудные негативы ценнее массы.** 200 фонематических двойников
  («термес», «Герман», фразы с «герм…») рисуют границу решения прямо
  возле слова — они полезнее тысячи случайных клипов.

Ambient-аудио для теста FA (подкасты/музыка/улица) **никогда** не входит
в train — иначе измеряем память, а не обобщение.

## Арбитр — кривая обучения

Все якоря выше дают вилку, а не точку. Настоящий метод:

```
обучить модель на подмножествах: 50 → 100 → 200 → 300 живых дублей
смотреть валидационную метрику:
  растёт на последнем шаге  → данных не хватает, доgatherивать
  вышла на плато            → стоп; дальше решает вариативность, не число
```

Этот эксперимент — первый после написания `train`. Он превращает вопрос
«хватит ли 300» из эвристики в измеренный факт для *нашей* модели.
