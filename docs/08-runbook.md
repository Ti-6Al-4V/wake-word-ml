# 08 — Runbook: поэтапный пайплайн

Зачем этот файл: открыть после любого перерыва и продолжить с нужного этапа,
ничего не вспоминая. Каждый этап: **что делаем → зачем → команда → как
проверить**. Теория в [01](01-theory.md), критерии качества в
[07](07-quality.md).

## Общая картина

Цель: маленькая CNN, которая на ESP32-S3 отвечает «да» только на слово
«Гермес». Главная метрика — **не точность узнавания, а false accepts
≤1 в 10 часов** (см. 07). Отсюда два потока данных:

- **позитивы** — слово в разных исполнениях (учим говорить «да» в любых условиях)
- **негативы** — всё остальное, особенно живая русская речь (учим говорить «нет»)

```
Этап  Что                          Команда / инструмент
────  ───────────────────────────  ─────────────────────────────────
 0    Окружение и микрофон         brew/uv/rustup
 1    TTS-позитивы                 make generate_tts
 2    Позитивы своим голосом       make record N=50 → make check
 3    Негативы                     make negatives
 4    Препроцессинг к 16kHz/1.2с   make preprocess IN=... OUT=...
 5    Аугментация позитивов        make augment
 6    Обучение CNN (burn)          cargo run --bin train
 7    Оценка (TPR, FA/час)         cargo run --bin eval
 8    Экспорт int8 → C++/ESP32     cargo run --bin export
```

Весь код — в git; аудио датасета — НЕ в git (`dataset/` в .gitignore),
после переустановки машины датасет набирается заново этими же командами.

## Этап 0 — окружение

Что: Rust (rustup), `uv` + `edge-tts` (для TTS), `ffmpeg` (для
препроцессинга). Микрофон — гарнитура JBL TUNE 305C USB-C (48kHz моно).

```bash
brew install ffmpeg uv edge-tts
rustup update
```

Проверка: `ffmpeg -version`, затем `make record N=1` — должен создать
один WAV. macOS спросит доступ к микрофону для терминала — разрешить.

Подводные камни:
- У JBL **системный input volume не управляется** (`missing value` в
  osascript). Если дубли тихие — крутить не настройки macOS, а
  софтвейрный гейн в рекордере (пока не добавлен).
- Микрофон у JBL на проводе: держать у подбородка, не на столе.

## Этап 1 — TTS-позитивы ✅

Что: синтез слова голосами Edge TTS. Зачем: дешёвое разнообразие
тембров и темпов без ручной записи; дополняет живой голос.

```bash
make generate_tts    # → dataset/raw/tts/, MP3
```

Выход: 3 текста × 2 голоса (SvetlanaNeural, DmitryNeural) × 5 скоростей
= 30 MP3. Голосов ru-RU в Edge реально два, не больше — разнообразие
тембров позже закрываем Qwen voice cloning'ом своим тембром (отложено,
см. vault-заметку) и вторым синтезатором.

Сэмпл для клона пишется отдельно: `make clone_sample` (по умолчанию 60с,
`SECS=120` — дольше). Это непрерывная связная речь одним файлом,
`dataset/raw/clone_sample.wav`; бинарь сам печатает текст для чтения
и проверяет уровень. Правило: живых позитивов в датасете не меньше,
чем клонированных.

Подводный камень: отрицательные скорости только через `=`:
`--rate=-25%`, иначе argparse ломает аргумент.

## Этап 2 — позитивы своим голосом (в процессе)

Что: наговорить 300–500 дублей (фаза 1; цель — растянуть до 500).
Зачем: живой голос — ядро позитивов; TTS без него даст модели выучить
тембры синтезаторов, а не слово.

```bash
make record          # 20 дублей
make record N=50     # 50 дублей
make check           # QC пачки
```

Ритм одного дубля: «Приготовься…» → 1 секунда → **окно записи 1.2с** —
говорить сразу после паузы, слово длится ~0.7с, запас есть.

Протокол:
- батчи по 50, между батчами перерыв: голос устаёт и тихо — это видно
  по цифрам QC;
- микрофон на одном расстоянии (дрейф уровня потом уберёт нормализация,
  но SNR у тихих дублей хуже);
- брак (тишина, клиппинг, слово в конце окна) **удалять вручную** —
  нумерация продолжается с максимального номера, перезаписи не будет;
- мусор в позитивах хуже нехватки: модель выучит мусор как часть слова.

QC-критерии (`make check`): пик 0.10–0.99, максимум до 93% окна.

Фаза 2 (после сборки кепки): переписать дубли на INMP441 — тот же
микрофон, что в устройстве; доменный сдвиг «гарнитура → MEMS на улице»
убивает точность сильнее всего (07-quality §2.1).

## Этап 3 — негативы ✅

Что: 6000 негативов + 6 фоновых шумов. Зачем: главная метрика
(false accepts ≤1/10ч) тренируется именно на них.

```bash
make negatives
```

Внутри:
1. **Speech Commands v0.02** — скачан в `dataset/raw/speech_commands`
   (105k клипов, ~2.3GB). `scripts/sample_speech_commands.py` берёт
   выборку 2000 (сид 42 — воспроизводимо) в `dataset/raw/sc_sample`
   и копирует 6 записей фоновых шумов в `dataset/raw/background`.
2. **Golos** — живая русская речь, самый ценный негатив.
   `scripts/extract_golos.py` режет фразы на окна 1.2с (тишину
   отбрасывает по RMS) в `dataset/raw/golos_clips`, лимит 4000.

⚠️ **Официальные ссылки Golos (sc.link) мертвы** — отдают пустой
ответ. Рабочее зеркало: HuggingFace `bonlime/golos-test`, папка
`crowd/`, 3 parquet по ~430MB. Аудио внутри parquet — уже WAV 16kHz
моно (схема: id, audio{bytes,path}, text, duration). Скрипт читает их
через `uv run --with pyarrow`.

Ambient 10 часов (подкасты/музыка/улица) для теста FA/час — **не**
скачаны и в train не входят никогда (07-quality §4).

## Этап 4 — препроцессинг ✅

Что: все аудио к единому формату. Зачем: модель принимает тензор
фиксированного размера и не должна реагировать на громкость.

```bash
make preprocess IN=dataset/raw/real       OUT=dataset/positive
make preprocess IN=dataset/raw/tts        OUT=dataset/positive
make preprocess IN=dataset/raw/golos_clips OUT=dataset/negative
make preprocess IN=dataset/raw/sc_sample  OUT=dataset/negative
```

Три преобразования (`src/bin/preprocess.rs`, декодирование через ffmpeg):
1. **16kHz моно** — частота фиксируется здесь, от неё зависят MFCC-параметры
   (кадр 480 сэмплов = 30мс);
2. **окно ровно 1.2с** (19200 сэмплов) — короткие файлы дополняются
   тишиной, длинные обрезаются;
3. **пиковая нормализация до 0.9** — убирает разницу громкостей между
   дублями: громкость не признак, признак — форма слова.

Идемпотентен: существующие выходы пропускает. Новые дубли → просто
перезапустить. Тихие файлы (пик < 0.0001) пропускает с предупреждением.

## Этап 5 — аугментация позитивов ✅

Что: 8 вариантов на каждый исходник. Зачем: 300–500 дублей мало —
модель запомнит конкретные записи; искажённые копии учат обобщать.

```bash
make augment    # dataset/positive → dataset/positive
```

Варианты (`src/bin/augment.rs`):

```
v1,v2  громкость ×0.7 / ×1.3         микрофон дальше/ближе
v3,v4  ленточная скорость ×0.9/×1.1  другой темп+высота (замена питч-шифта)
v5-v7  белый шум SNR 20/10/5 дБ      фон: тихо/средне/улица
v8     сдвиг слова ±10% окна         слово стартует не в ту же миллисекунду
```

Детерминизм: сид = хэш имени файла + номер варианта → повторный запуск
ничего не меняет. Исходники = файлы без `_v` в имени (аугментированные
не аугментируются повторно). Итог: исходники ×9.

Негативы не аугментируем: их и так 6000, разнообразия хватает.

## Этап 6 — обучение (заглушка, пишем вместе)

`src/bin/train.rs` пока пустой. План (детали в
[03-training.md](03-training.md), но там API burn 0.14 — у нас 0.21,
адаптируем): датасет 70/15/15 стратифицированно → MFCC (40 кадров ×
20 фичей на окне 1.2с/16kHz) → маленькая CNN → бинарная классификация.
Осознанно пишем вместе — это ядро ML-понимания проекта.

## Этап 7 — оценка (заглушка)

`src/bin/eval.rs`. Критерии из [07-quality.md](07-quality.md):

```
TPR ≥95%          своё слово, чистые записи (+ вариации с шумом)
FA ≤1 в 10 часов  ambient-стриминг (подкасты/музыка/улица)
0 / 500           фонематические двойники («термес», «Герман», фразы)
задержка ≤500мс   от конца слова (уже на ESP32)
```

## Этап 8 — экспорт и железо (заглушка)

`src/bin/export.rs`: веса → int8 `.bin`. Дальше ручной C++ forward
pass на ESP32-S3 (~200 строк, без TFLite) — [04-deploy.md](04-deploy.md),
интеграция в кепку — [05-integration.md](05-integration.md).

## Повторный цикл после новых дублей

Наговорил батч → весь цикл идемпотентен, просто:

```bash
make check                                                           # QC
make preprocess IN=dataset/raw/real OUT=dataset/positive             # новые дубли
make augment                                                         # докинет варианты только для новых
```
