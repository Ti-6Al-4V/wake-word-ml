# Путь обучения: самостоятельно создать wake-word детектор

Цель — понять и собрать цепочку **PCM → признаки → обучаемая модель →
потоковое событие → устройство**. Проект даёт практику DSP, supervised ML,
экспериментальной оценки и embedded inference. Он не заменяет всё машинное
обучение; освоенные градиенты, разбиение данных и диагностика переносятся
на другие задачи.

## Как проходить

На каждом шаге: **объясни задачу → предскажи результат → реализуй или
измени → измерь → объясни расхождение**. Команда, завершившаяся без ошибки,
ещё не означает, что тема освоена. Переходи дальше после критерия зачёта.

Подробные задания и численные проверки — [10-labs](10-labs.md).
Результат каждого эксперимента сохраняй по [шаблону](experiment-template.md).
Готовый код читай после собственной попытки на маленьком примере.
Если работаешь с агентом, проси вопросы, проверку вывода и подсказку к
следующему действию; полное решение лабораторной — после своей реализации.

Длительность зависит от пробелов: один этап может занять несколько занятий.
Не нужно сначала собирать тысячи записей: L1–L4 выполняются на синтетических
данных, а первичная проверка CNN — на маленькой выборке.

## Шаг 0. Сформулировать задачу

V1 — детектор произнесения слова «Гермес» твоим голосом. Обобщение на других
людей проверяется отдельно. Различение обращения к ассистенту и упоминания
имени — тоже отдельная задача: само слово акустически может быть тем же.

Условия успеха задаём одновременно: доля обнаруженных произнесений,
ложные события в час, задержка. Всегда молчащий детектор имеет FA/h=0,
но бесполезен. Рабочие цели: recall ≥95%, FA/h ≤0.1, задержка ≤500 мс
после конца слова в заранее перечисленных условиях.

**Зачёт:** выполнена L0, спорные случаи имеют однозначные метки.

## Шаг 1. От воздуха к числам

PCM — последовательность измерений сигнала. Для речи здесь выбран mono
16 kHz, PCM16. Это практичный бюджет, а не утверждение, что выше 8 kHz
в речи нет информации. Перед снижением частоты нужен антиалиасинг-фильтр.

Различай три временных масштаба:

- 1 отсчёт = 1/16000 секунды;
- 480 отсчётов = 30 мс, один кадр признаков;
- 19200 отсчётов = 1.2 с, полный вход классификатора.

Шаг потока 100 мс — четвёртая величина, не размер кадра MFCC.

**Сделай L1. Зачёт:** по сигналу предсказываешь пики спектра, объясняешь
оконную функцию и aliasing. FFT — быстрый алгоритм вычисления DFT.

## Шаг 2. Извлечение признаков

Текущий путь:

```
PCM → pre-emphasis → кадры 480, шаг 480 → Hamming → FFT 512
    → power → 20 mel-полос → ln(max(energy, 1e-5))
    → DCT, все 20 коэффициентов → CMVN по времени → [40,20]
```

Нейросети могут учиться на сыром PCM. Здесь ручные признаки уменьшают
объём входа и дают понятный первый вариант. Log-mel — полноценная
альтернатива с тем же числом полос. После DCT ось коэффициентов уже не
частота; DCT 20→20 не сжимает размер и не гарантирует полной декорреляции.

CMVN вычитает среднее каждого коэффициента и делит на его стандартное
отклонение с epsilon. Она уменьшает некоторые постоянные смещения,
но не гарантирует независимость от микрофона, шума или усиления:
log-floor, шум, клиппинг и состав окна нарушают идеальную инвариантность.

```
make mfcc-check FILE=dataset/positive/germes_real_0020.wav
```

Подставь существующий подготовленный файл. Утилита показывает **отдельно**
PCM RMS и норму MFCC: после CMVN последняя не является энергией звука.

**Сделай L2. Зачёт:** можешь пройти путь одного кадра и подписать все оси.

## Шаг 3. Один обучаемый нейрон

Начни без Burn: `z=w·x+b`, sigmoid, BCE, ручные производные и SGD.
Обучение меняет параметры; сама формула forward остаётся той же.

```
p = sigmoid(z)
dL/dz = p-y
dL/dw = (p-y)*x
w_new = w_old - lr*mean(dL/dw)
```

Sigmoid выдаёт score в [0,1]. Интерпретировать 0.9 как «90% надёжности
в жизни» без проверки калибровки нельзя, особенно при другом балансе
классов и других условиях эксплуатации.

**Сделай L3. Зачёт:** выводишь градиент и проверяешь его конечной разностью.

## Шаг 4. Сеть и автоматическое дифференцирование

Композиция линейных слоёв без нелинейности остаётся линейной. Скрытая
нелинейность позволяет получить более сложную границу решения. Backprop
применяет цепное правило от loss назад через вычислительный граф.

Autodiff хранит нужные промежуточные значения и выполняет этот расчёт.
Adam использует оценки первого и второго моментов градиента; базовый lr
всё равно выбираешь ты. Изучи его после рабочего ручного SGD.

**Сделай L4. Зачёт:** forward, градиенты и один шаг совпадают с фреймворком
в заранее выбранном численном допуске.

## Шаг 5. Данные и разбиение

Собери небольшой набор позитивов, своей речи без слова и двойников тем же
микрофоном. Добавь реальные фоны. TTS расширяет варианты, но не заменяет
новые живые записи. Аугментация одного дубля не создаёт нового независимого
говорящего или новой сессии.

Читай [02-dataset](02-dataset.md) перед массовым сбором. Текущий split
группирует производные по именам, но не гарантирует разделение всех сессий
и дикторов. При добавлении файлов состав сплитов может измениться.

Для серьёзного сравнения нужны фиксированные списки и метаданные
source/session/speaker. Валидация — для решений, финальный тест — для
отдельной оценки после выбора. Для новых условий нужен отдельный набор.
Аугментации создавай из train; общие фоновые записи между train и test
тоже могут завышать качество.

**Зачёт:** можешь объяснить происхождение каждого файла, почему он в этом
сплите и какую независимость проверяет оценка.

## Шаг 6. Baseline, затем CNN

Сначала константный классификатор и логистическая регрессия на тех же
признаках. Baseline позволяет проверить, добавляет ли CNN пользу.

```
[1,40,20] → Conv 1→16,3×3 → ReLU → Pool 2×2 → [16,19,9]
         → Conv 16→8,3×3 → ReLU → Pool 2×2 → [8,8,3]
         → Flatten 192 → Dropout → Dense 16 → ReLU → Dense 1
```

4425 параметров — 17700 байт float-весов. Это не объём всей RAM.
Свёртка повторно использует один фильтр в разных позициях. На MFCC
локальность по оси коэффициентов — проверяемое допущение архитектуры.
Flatten→Dense сохраняет зависимость от позиции; устойчивость к сдвигам
и темпу нужно измерять, а не приписывать автоматически MaxPool.

**Сделай L5. Зачёт:** ручная свёртка верна, формы и MAC посчитаны,
модель способна намеренно переобучить маленький train-набор.

## Шаг 7. Настоящий цикл обучения

Когда данные подготовлены:

```
make split-check
make train E=1
make train E=30
make eval
```

Первая команда проверяет только реализованные правила группировки.
Одна эпоха — проверка работоспособности; 30 — старт эксперимента, а не
гарантия достаточного обучения. Каждый `make train` начинает заново и
перезаписывает веса/логи. Сохраняй артефакты между прогонами.

Разбери `train.rs`: forward → loss → backward → optimizer.step.
Валидация использует inference-модель без dropout. Train loss измеряется
во время изменения весов, val loss — после эпохи, поэтому это не строго
одинаковые условия измерения даже при одном датасете.

| Наблюдение | Следующая проверка |
|---|---|
| Train и val высокие | Метки, нормализация, LR, tiny-overfit, ёмкость |
| Train падает, val растёт | Переобучение, различие доменов, размер val |
| Loss NaN или резко скачет | Входы, градиенты, LR, численная устойчивость |
| Clip-метрики хорошие, поток плохой | Положение слова, фон, постобработка, доменный сдвиг |
| Синтетика лучше живых записей | Состав данных и домен; это ещё не доказательство shortcut |

Чекпоинт по val loss — разумный старт. Для конечного устройства сравнивай
кандидатов по recall при требуемом FA/h на development-потоке.

**Зачёт:** по ошибкам предлагаешь проверку, которая различит хотя бы две
возможные причины. Одного падения train loss недостаточно.

## Шаг 8. Проверять гипотезы

Сделай L6. Не меняй одновременно признаки, аугментации и архитектуру.
Dropout и weight decay — варианты для сравнения, их улучшение не гарантировано.
При обучении на подмножествах сохраняй val; при нескольких seed показывай разброс.

Свою речь, на которой нашёл ошибки и которую добавил в train, можно
использовать для диагностики запоминания. Улучшение обобщения проверяй
на следующей отдельной сессии. Финальный test не превращай в список
новых обучающих примеров в каждом цикле.

**Зачёт:** минимум три воспроизводимых сравнения с честными выводами.

## Шаг 9. Из классификатора сделать детектор

Классификатор отвечает за одно окно. Детектор принимает поток, накапливает
окна и превращает score в события. Текущий `make stream FILE=...` использует
окно 1.2с, шаг 100мс, два превышения подряд, cooldown 2с. Вход — PCM16
16kHz WAV без слова. Его вывод — наблюдаемые FA/h для разных порогов.

Для выбора порога нужен development-поток. Для финальной проверки — другой
поток с уже фиксированными параметрами. Поддержка разметки позитивных
событий и автоматического расчёта задержек ещё не реализована: это L7.

**Зачёт:** есть протокол событийной оценки из [07-quality](07-quality.md),
разделены наблюдаемые показатели и статистические границы.

## Шаг 10. Перенести на устройство

Порядок: float-экспорт → CPU forward → совпадение промежуточных тензоров
→ MFCC parity → I2S и поток → измерения → оптимизация/int8.
Не начинай с квантования: иначе ошибки порта смешаются с его погрешностью.

`export.rs` — заглушка, C++ в [04-deploy](04-deploy.md) — образец для
реализации. Измеренных времени работы и энергопотребления ESP32 в этом
репозитории пока нет. Сначала воспроизведи float-путь, затем решай, что
оптимизировать по реальному профилю.

**Сделай L8. Зачёт:** численная проверка и отчёт о ресурсах на железе.
