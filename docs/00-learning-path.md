# План: детектор «Гермес» для любого человека

Цель проекта — модель, которая срабатывает на «Гермес» от **любого**
человека, на любом микрофоне, и молчит на остальной речи и шуме. Её
можно распространять. Учебная цель — самостоятельно пройти путь
**PCM → признаки → CNN → событие в потоке → ESP32** и понимать каждое звено.

Правило каждого шага: **прогноз → реализация → замер → объяснение
расхождения**. Результат — карточка по [шаблону](experiment-template.md).
Код лабораторных пишешь сам; готовый код проекта читаешь после своей попытки.

## Что нужно датасету (суть)

Сейчас позитивы — это 306 твоих дублей и два голоса Edge TTS, то есть
около трёх дикторов. Негативы — 6000 чужих людей на чужих микрофонах.
На таких данных сеть учит «голос Жеки в JBL», а не слово. Для модели
«для всех» нужны четыре правила:

1. **Дикторы считаются по людям, не по файлам.** 300 дублей одного
   человека — это один диктор. Позитивам нужны сотни разных голосов.
2. **Каждый источник даёт оба класса.** Если TTS-голос говорит только
   «Гермес», сеть выучит «звучит как TTS = Гермес». Тот же голос должен
   сказать «термес», «Герман», «гермет», «Гермиона» и обычные фразы.
   То же касается живых людей: слово и обычная речь от каждого.
3. **Искажения — обоим классам.** Шум, фоны и скорость применяются и к
   негативам (`make augment-neg`), иначе «шумно = Гермес».
4. **Test — только живые люди, которых нет в train.** Папки
   `dataset/holdout/`. Это единственная линейка, которой можно верить.
   Синтетика в test запрещена.

Откуда брать голоса:

| Источник | Что даёт | Класс |
|---|---|---|
| Живые люди (друзья, родные, коллеги) | Правду: реальные голоса и микрофоны | holdout-test; часть людей — в train |
| TTS с клонированием голоса по короткому образцу (Qwen3-TTS) + образцы дикторов из Common Voice ru | Сотни синтетических дикторов | «Гермес», двойники, фразы — одними и теми же голосами |
| Edge TTS, Piper, Silero | Ещё несколько голосов | Оба класса |
| Твои записи | Один диктор | train, оба класса |
| Golos, Speech Commands, Common Voice | Чужая речь | Негативы |
| Фоны: улица, кухня, ТВ, музыка | Шум | Аугментация обоих классов и поток для FA/h |

Лицензию каждого корпуса и TTS проверь до обучения модели, которую
будешь распространять: модель наследует ограничения данных. Common Voice —
CC0, Speech Commands — CC BY 4.0, у Golos — собственная лицензия
(читать PDF в репозитории sberdevices/golos), Qwen3-TTS — Apache 2.0.

## Этапы

Сроки ориентировочные, при занятиях по вечерам.

### Этап 0. Контракт задачи (1 вечер)

- **Читать:** [07-quality](07-quality.md).
- **Делать:** L0 из [лабораторных](10-labs.md).
- **Зачёт:** записаны метки для 10 спорных случаев, целевые recall и
  FA/h, список условий (микрофоны, дистанции, шумы).

### Этап 1. Как учится нейросеть (1–2 недели)

- **Читать/смотреть:** 3Blue1Brown, серия «Neural networks» (главы 1–4);
  Andrej Karpathy, «The spelled-out intro to neural networks and
  backpropagation: building micrograd».
- **Делать:** L3 (нейрон, ручной градиент), L4 (XOR, backprop, сверка с Burn).
- **Зачёт:** выводишь градиенты на бумаге, они совпадают с конечными
  разностями и с Burn.

### Этап 2. Звук и признаки (1 неделя)

- **Читать:** [01-theory](01-theory.md), разделы про PCM, спектр и MFCC;
  Haytham Fayek, «Speech Processing for Machine Learning: Filter banks,
  MFCCs and what's in-between».
- **Делать:** L1 (DFT руками, окна, aliasing), L2 (MFCC по шагам, что
  теряет каждое преобразование).
- **Зачёт:** проходишь путь одного кадра от PCM до CMVN и подписываешь оси.

### Этап 3. CNN на чистом полигоне (1–2 недели)

Сначала CNN учится там, где данные сбалансированы и дикторов тысячи:
Speech Commands уже лежит в `dataset/raw/speech_commands`. Если модель
плохая, виновата модель, а не данные. Это отделяет изучение CNN от
борьбы с датасетом.

- **Читать:** Stanford CS231n, конспект «Convolutional Neural Networks»;
  Zhang et al., 2017, «Hello Edge: Keyword Spotting on Microcontrollers»;
  Warden, 2018, «Speech Commands: A Dataset for Limited-Vocabulary Speech
  Recognition».
- **Делать:** L5 (baseline, ручная свёртка, tiny overfit) и L5b
  (классификатор 10 слов Speech Commands на тех же MFCC).
- **Зачёт:** CNN статистически лучше логистической регрессии, формы,
  параметры и MAC посчитаны руками, объяснено, почему.

### Этап 4. Данные для любого голоса (2–4 недели, главный этап)

Это центральная работа проекта: качество модели определяется здесь, а не
архитектурой. Работа близка к ETL, которым ты занимаешься на работе:
источники, схема имён, идемпотентность, манифесты.

Порядок важен:

1. **Holdout первым.** 20+ человек (лучше 50), от каждого 10 «Гермесов»
   и минута обычной речи, на их устройствах. Имена файлов `p017__...`.
   `make record_holdout P=p017`, `make record_holdout_speech P=p017`,
   `make holdout`. До финальной оценки эти записи не слушаешь и не
   правишь модель под них.
2. **Свои негативы.** `make record_speech`, `make chop`,
   `make record_confusables WORD=...` — чтобы твой микрофон перестал
   быть признаком класса.
3. **Генератор синтетических дикторов.** Скрипт: берёт короткие образцы
   разных дикторов Common Voice ru, клонирует голос и синтезирует
   «Гермес» (отдельно, с `!`/`?`, внутри фразы), 3–5 двойников и 2–3
   обычные фразы. Имена `<генератор>_<диктор>__<текст>_<n>` — по `__`
   сплит держит диктора целиком в одном наборе. Стартовый ориентир —
   500 голосов; нужно ли больше, покажет кривая обучения.
4. **Аугментации обоим классам:** `make augment`, `make augment-neg`.
5. **Проверка:** `make split-check` (test должен быть holdout), QC по
   [02-dataset](02-dataset.md).

- **Читать:** [02-dataset](02-dataset.md), [09-dataset-sizing](09-dataset-sizing.md),
  README проектов openWakeWord и microWakeWord (как они учатся на синтетике).
- **Зачёт:** для любого файла можешь назвать источник, диктора, класс и
  набор; ни один источник не предсказывает класс сам по себе.

### Этап 5. Обучение и эксперименты (2 недели)

- **Читать:** [03-training](03-training.md).
- **Делать:** L6. Сначала базовая модель, затем по одному изменению:
  - ёмкость: 4.4K параметров против 20–50K (ESP32-S3 потянет больше, чем
    есть сейчас — это надо измерить, а не предполагать);
  - `augment-neg` вкл/выкл;
  - только синтетика против синтетики с живыми людьми в train;
  - CMVN по окну против нормализации по статистикам train, энергетический
    гейт в потоке (CMVN по окну растягивает шум тишины до дисперсии 1).
- **Метрика:** recall на holdout-людях с разбивкой по людям и FA/h.
- **Зачёт:** три карточки экспериментов с прогнозом, замером и выводом.

### Этап 6. Детектор в потоке (1–2 недели)

- **Делать:** L7. Запиши несколько часов фона без слова (ТВ, подкасты,
  разговоры, кухня) — `make stream`. Реализуй разметку и event recall.
- **Зачёт:** порог, K и cooldown выбраны на development-потоке, цифры
  получены на отдельном финальном потоке.

### Этап 7. ESP32 (2–4 недели)

- **Читать:** [04-deploy](04-deploy.md), [05-integration](05-integration.md).
- **Делать:** L8. Экспорт весов → CPU forward → совпадение со слоями Burn →
  MFCC на C++ → I2S → замеры RAM/времени/тока → int8.
- **Зачёт:** численный отчёт о совпадении и замеры на железе.

### Этап 8. Самостоятельно (открыто)

L9: второе слово или звук, план и эксперимент без подсказок.
